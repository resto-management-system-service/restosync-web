## Preconditions

- `.env.local` has `NEXT_PUBLIC_DISABLE_AUTH=true` (Clerk is fully bypassed in dev)
- `pnpm dev` running; the MSW mock backend starts automatically (`src/components/mock-gate.tsx`)
- The mock DB is faker-seeded and **resets on every page reload** — created/edited/deleted
  rows are per-session only

## Manual test script

### 1. Menu items — list

1. Go to **Dashboard → Menu → Items** (`/dashboard/menu`).
2. Expect ~14 seeded rows: **Name**, **Category** badge (resolved name), **Price**
   (formatted, e.g. `$11.24`), **Status** (Available / Unavailable), row actions.
3. Footer shows `N row(s) total`, `Page 1 of 2`, rows-per-page selector.
4. Type in **Search items…** → list filters by name client-side; **Reset** clears it.
5. Click the **Name** / **Price** column headers → client-side sort toggles.

### 2. Menu items — create

1. Click **Add Item** → `/dashboard/menu/new`, "Create Menu Item" form.
2. Click **Add Item** with the form empty → inline errors ("Item name must be at least
   2 characters.", "Price must be greater than 0.", "Please select a category.").
3. Fill **Item Name** = `Truffle Arancini`, **Price** = `13.50`, **Category** =
   `Appetizers`, **Currency** stays `USD`, optional **Description**.
4. Submit → toast **"Menu item created"**, redirect to the list.
5. The new row appears immediately (no reload) — price shows `$13.50` (13.50 → 1350
   cents → formatted), category `Appetizers`, status `Available`. Total count +1.

### 3. Menu items — edit

1. Row **⋮ → Update** → `/dashboard/menu/<id>`, "Edit Menu Item" form pre-filled
   (price shown in dollars).
2. Change **Price** to `9.99`, submit → toast **"Menu item updated"**, list reflects
   `$9.99`.

### 4. Menu items — delete

1. Row **⋮ → Delete** → "Are you sure?" dialog.
2. **Continue** → toast **"Menu item deleted"**, row disappears from the list
   immediately, total count −1. (**Cancel** / **✕** dismisses with no change.)

### 5. Categories — list + create

1. **Dashboard → Menu → Categories** (`/dashboard/menu/categories`).
2. Expect 4 seeded rows (Appetizers/Mains/Desserts/Drinks) with **Sort Order** +
   **Status**.
3. **Add Category** → fill **Name** (≥2 chars) + **Sort Order** → submit → toast
   **"Category created"**, new row appears.

### 6. Categories — delete guard (contract 409)

1. Row **⋮ → Delete** on a category that still has items (e.g. **Appetizers**) →
   **Continue**.
2. Expect error toast **"Cannot delete category — Move or remove its menu items first."**
   The category is **not** removed. (Known nit: the confirm dialog stays open on error.)
3. Delete an **empty** category → succeeds, row removed.

### 7. Auth-disabled placeholders

With `NEXT_PUBLIC_DISABLE_AUTH=true`, these render an "unavailable in dev" notice
instead of Clerk UI: `/dashboard/workspaces`, `/dashboard/workspaces/team`,
`/dashboard/billing`, `/dashboard/exclusive`, `/dashboard/profile`, `/auth/sign-in`,
`/auth/sign-up`. The sidebar shows a static "Dev Workspace" / "Dev User".

## Known limitations (by design — see the spec)

- Mock DB is in-memory per browser session (resets on reload).
- Browser and Node MSW instances have independent stores → menu list/detail are
  **client-fetched** (no SSR prefetch) so mutations stay consistent with the view.
- `GET /menu/items` returns a bare array → table pagination is client-side.
- Response shapes come from `src/features/menu/api/types.ts` (OpenAPI types responses
  as `unknown`).
